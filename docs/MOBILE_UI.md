# 手机端界面规范

## 2026-09-12 整体呼吸感

用户希望整个手机 UI 与细节更有呼吸感。本节取代上一阶段“可见静止界面没有装饰循环”的要求：现在允许有限的 CSS 装饰呼吸，仍不添加常驻 JavaScript 帧循环。保持浅色主题、布局、文字与点击区域稳定，不对整张页面或正文做缩放、抖动或亮度变化。

采用两层面积受限的浅蓝/珍珠暖光，静态渐变只动画透明度和小幅位移；输入器细边、可用发送/创建按钮的柔和光晕、链路图标与面板把手以不同周期轻微变化。阴影/渐变本身保持静态，不逐帧改变 blur、box-shadow 或尺寸。弹窗打开时暂停背景与输入器装饰，输入焦点时稳定边缘；禁用按钮不呼吸。隐藏页面和减少动态停用新增循环，恢复后不补播积压帧。

验收包括呼吸前后文字/按钮边界一致、动画只修改合成属性、叠层不拦截点击、发送/停止与菜单、新建/禁用态、四种手机画幅以及减少动态。截图保留两个呼吸相位；结果是桌面浏览器模拟，不作为 Android 真机帧率或能耗结论。范围仅限隔离预览样式，不修改正式入口、真实链路和 Windows 应用。

## 2026-09-12 顶部轻量链路状态

用户认可浅色主题，要求补充小动画并将链路延迟等信息放到顶部，保持小巧。复用标题下原预览提示的位置，替换为约 28px 的单行状态条：明确“模拟”标识、电脑在线/恢复中/离线、往返延迟示例和加密/只读状态。HostConnection 当前没有 RTT 字段，隔离预览在线时显示固定 48 ms 示例，离线/恢复中为“—”；不把本机模拟调用耗时或生成首字耗时伪装成链路测量，不新增测速请求、定时随机数或服务端契约。

状态与数值短距离渐入，在线任务运行时小状态点轻微脉动，停止/离线/隐藏/减少动态时停用。默认静止后无循环，背景与对话动效保持。验收覆盖四种手机画幅的高度/单行边界、模拟标识、任务运行与停止、离线读态、减少动态及正式入口边界。本轮仍仅启用手机隔离预览，正式测量接入以后再按实际数据源实施。

实现边界：模拟组件与 48 ms 示例只放在 mobile-preview 中，共享 App 提供仅在 preview/mobileMotion 启用时使用的可选顶部呈现插槽；未提供时保留原预览提示。正式入口不导入模拟组件，不放宽 DSH 边界检查。

## 2026-09-12 轻松浅色主题

用户否定手机预览的压抑深色，改为雾白背景、低饱和灰蓝层次与柔和蓝色主操作。保持原布局、圆角、文字缓冲与动效；启用现有浅色 token，并在隔离样式中统一输入器、任务抽屉、底部菜单、新建弹窗、设备管理及外部预览画框。正文采用深灰蓝，辅助文字保持可读，成功/警告/错误仍可区分。背景仅静态轻渐变，不引入新资源或逐帧效果。

验收：360/393/412px 和短横屏布局，默认阅读、草稿/发送、任务栏、模型/权限菜单、新建与设备页的填充/文字对比，以及已有缓冲回复和动画回归。范围只含 mobile-preview 的 CSS/HTML，不更改正式 Web 入口、共享业务逻辑或 Windows 预览。

## 2026-09-10 隔离动效预览

本轮追加：用户要求先短暂缓存返回文字再流式呈现，并细化按钮/弹窗。只在 mobileMotion 预览中启用：新到达的 assistant 正文在组件内存中缓冲约 600 ms，按字素与积压量平滑释放；完成后最多约 900 ms 收尾，停止/错误/减少动态时立即显示已收到的原文，后台暂停且返回时追上。历史消息和任务切换后的已有内容直接显示；不修改原快照、网络、任务状态或实际发送能力。保留已有 Markdown 语义，避免切断 emoji/组合字符，呈现帧只更新当前正文。

输入菜单与新建任务弹窗使用统一的可中断进出动画：小幅缩放/位移、轻微回弹、遮罩淡入及短距离的内容渐入；退出立即 inert，快速重开承接当前位置。按钮使用短按下和稍缓的回弹，选中图标给轻反馈。保持触控尺寸、焦点、返回键、减少动态和静止无帧循环。验收包含突发/稀疏文字、短答/长答、停止/切任务、快速弹窗反向、360px/短屏及边界构建；不宣称实测 Android 60 FPS。

用户要求继续保持隔离并优化手机 UI 的细节动画与帧率。本轮复用现有 App、Sidebar、消息和 CodexServeClient，新增独立 mobile-preview 入口；新的呈现行为通过默认关闭的预览参数开启，专属样式只由预览入口导入。只使用内存模拟数据，无 Owner 登录、配对、Relay、app-server 或真实任务请求，不部署正式站点，也不改 Windows 预览。

- 任务抽屉、环境面板和输入菜单：统一移动端间距、44px 触控目标、透明度/位移动效，补齐菜单退出动画；快速切换取消旧动画，退出节点 inert，返回/Esc/焦点仍遵守原交互。
- 对话：新消息轻入场，已有流式文字不反复整条动画；按任务保留草稿和阅读位置，只有靠近末尾时跟随增长，阅读历史时提供“回到最新”。布局/滚动更新在 requestAnimationFrame 内合并，目标 60 FPS，静止时无空转循环。
- 输入器：保留原发送、附件、模型/推理/权限语义，优化触控反馈、多行高度、安全区和小高度视口；不将装饰动画当成动作成功。
- 验收：360/393/412px 与短横屏的布局，任务切换/草稿、菜单连续开闭、返回键/焦点、模拟流式发送/停止、阅读历史不被拉回、减少动态与网络隔离。浏览器帧时只报告实测环境，不冒充 Android 真机帧率或软键盘验收。

本阶段已完成上述隔离实现与桌面浏览器检查，记录见 PROGRESS.md 和 `.tmp/mobile-ui-preview-qa/validation.json`。应用布局写入按 60 FPS 目标限频；CSS/浏览器动画跟随实际刷新节奏。正式入口默认不启用，尚未部署到安卓浏览器使用的正式站点。

本文较早的扫码/SAS、固定单项目及禁止受控 full-access 描述属于历史；当前认证与会话范围以 DOCKER_GATEWAY_HANDOFF.md、WINDOWS_RELEASE.md 及 PROGRESS.md 的生产记录为准。本轮只验证这些已有能力的预览呈现，不更改认证方案。

## 1. 产品决定

- 手机端是 P0 主客户端；电脑 Web 与手机使用同一 React DOM/PWA 组件树，不单独设计第二套产品。
- 第一阶段先交付域名即用的 Web/PWA；如需 APK，再增加不复制业务状态机的薄 TWA/WebView 壳。
- 不再重做任务列表、对话、输入器、附件、工具、diff 和审批；直接使用已经验收的 DSH-derived 组件树，只补移动端交互薄层。
- 使用 Codex Plus 自有品牌，保留第三方许可与归属；不复制 Codex Desktop 闭源 renderer、未授权素材或 OpenAI 商标。

“直接用”的准确含义是**采用许可清晰的现成开源客户端，再做最小的 Codex-only 适配**。`openai/codex` 没有开源 Codex Desktop 图形前端；证据和采用边界见 [FRONTEND_SOURCE.md](FRONTEND_SOURCE.md)。

## 2. 官方流程与自托管流程的对应

官方 Remote 要求手机与主机登录同一个 ChatGPT 账号和 workspace，并通过桌面端显示的二维码配对。Codex Plus 复用这个用户心智，但不能要求、收集或代理用户的 OpenAI 登录凭据。

| 官方 Remote | Codex Plus |
| --- | --- |
| 同一 ChatGPT 账号/workspace | 同一组已配对的 Codex Plus 设备身份 |
| 桌面端开启 Remote | Windows Agent 开启远程访问 |
| 手机扫描桌面二维码 | Android/Web 客户端扫描 Windows Agent 二维码或输入一次性口令 |
| 官方安全 Relay | 自有域名 + 阿里 Relay + 应用层 E2EE |
| Remote 中选择主机和聊天 | Codex Plus 客户端中选择 Windows 主机和同一 Codex thread |
| 官方账号负责设备撤销 | Windows Agent 的“已连接设备”负责撤销 |

手机配对成功后应像“已登录”一样长期可用，但界面明确写“已连接到你的设备”，不显示伪造的“使用 OpenAI 登录”。OpenAI/Codex 的正常登录态只由本机官方 Harness 使用，永不进入手机/Web 客户端或 Relay。

## 3. 信息架构

```text
首次配对 / 本地解锁
└─ 主应用
   ├─ 侧边抽屉
   │  ├─ 新建任务
   │  ├─ 搜索任务
   │  ├─ 最近任务（今天 / 昨天 / 更早）
   │  ├─ 主机与工作区
   │  └─ 设置 / 已连接设备
   ├─ 对话页
   │  ├─ 顶栏：返回、标题、主机状态、更多
   │  ├─ 时间线：消息、工具、命令、diff、审批
   │  └─ 输入器：文本、附件、发送 / 停止
   └─ 底部面板
      ├─ 图片与文件
      ├─ 审批详情
      ├─ 任务详情
      └─ 连接与错误详情
```

默认打开上次查看的任务。没有上次任务或目标已不可用时进入最近任务列表，不自动向任何 thread 发送动作。

## 4. 核心页面

### 4.1 配对与解锁

- 手机直接浏览 `https://gateway.example.com` 并登录 owner 账户；没有本地设备授权时，首屏只要求输入电脑 `/manage` 显示的 8 位配对码。
- 配对码兑换只走同源认证 API；底层 invitation 仍绑定短时 nonce、主机 id、Relay origin 和公钥。该 invitation 已由当前授权电脑的E2EE管理动作预先授权，因此 Windows 后台自动批准，不再显示或人工核对 SAS。
- 错码、过期、重复使用或 Windows Companion 离线分别给出可操作说明；页面不请求相机权限。绑定成功后保存本浏览器设备授权，以后账密登录自动恢复。
- 已配对设备再次打开时直接进入应用；Android 优先用系统安全存储，Web 使用不可导出密钥与本地解锁策略。
- 配对失败、过期和主机离线分别说明，不用一个笼统的“连接失败”。

### 4.2 任务抽屉

- 行为接近 ChatGPT 手机端侧栏：从左侧滑入，点击遮罩或 Android 返回键关闭。
- 顶部固定“新建任务”和搜索；下面按时间分组显示任务。
- 任务行只放标题、工作区/主机的短标签和运行状态，不堆叠技术 id。
- `running`、`waiting_approval`、`offline` 用文字和低干扰图标共同表达，不能只依赖颜色。
- 切换任务前保留当前草稿；不自动中断正在运行的任务。

### 4.3 对话页

- 使用 ChatGPT/Codex 风格的全宽时间线，避免把每条 Agent 输出都放进厚重气泡。
- 用户消息保持紧凑；Agent 回复以正文为主，Markdown、代码、图片和列表遵循窄屏排版。
- 命令、工具、文件修改、测试结果和 diff 使用可折叠卡片；默认显示动作、状态和结论，详情按需展开。
- 流式回答底部显示当前动作和停止按钮；断线后保留最后快照并明确显示数据时间。
- 只有 Codex Plus 自己有证据的动作标记来源；其余历史统一显示为其他 Codex 客户端，不猜测来自 App 或 VS Code。

#### 4.3.1 手机任务详情入口

- 手机顶栏不照搬桌面的“打开位置 / 环境信息 / 文件侧栏”三个按钮，也不得把这些信息全部隐藏。右上只保留一个至少 44px 的“环境信息”入口；待审批、离线或运行中等重要状态可在该入口显示低干扰角标，但不能只靠颜色表达。
- 点击入口打开带遮罩的底部面板。面板保留桌面 Codex 的信息层级：环境信息（变更、本机/工作区、Git 分支、提交/推送、拉取请求）、子智能体、来源；深色背景使用 `#2D2D2D`，顶部圆角 24px，内容内部滚动并为底部安全区留白。
- “变更”只有在当前任务明确具备文件浏览与 shell 能力、且不是本地 preview 时才可进入全屏 diff；否则显示不可用原因。进入 diff 后，手机返回键先回到对话，不得直接退出任务。
- “本机/工作区”可进入面板内的工作区位置详情并复制路径；“在工作电脑打开”在 Windows Agent 提供真实能力前保持禁用。不得点击后伪装成功。
- “来源”首屏展示最近已加载项；“查看全部”只展开当前客户端已经持有的来源列表，不读取未加载历史、不访问任意文件、不触发 Relay/session RPC。点击遮罩、关闭按钮或 Android 返回键关闭面板，不能清空输入草稿或改变对话滚动位置。

### 4.4 底部输入器

- 固定在安全区上方，视觉接近 ChatGPT 手机端的圆角多行输入器。
- 输入框下只保留一行轻量控制：左侧 `+` 与权限，右侧模型、推理强度和发送/停止；不用齿轮汇总，不把每个控件画成常驻卡片。
- 左侧 `+` 打开靠近输入器的单块圆角菜单。首版只展示真实可用的图片/附件动作；文件夹、目标、计划模式和插件等到 Agent 声明对应能力后再显示，不伪装已实现。
- 权限文字紧邻 `+`，菜单提供“请求批准 / 只读”；参考图中的“帮我批准 / 完全访问”只作为禁用说明项展示，完全访问使用橙色警示。MVP 不接受手机端提权；未来若设计 Windows 本机一次性能力，须先单独更新安全文档与验收。右侧模型与推理强度各自打开同款圆角菜单。
- 菜单普通行保持透明，只有当前选项和按下态显示带动画的圆角底板；不用 radio 卡片墙或多层边框。
- 输入文本原样发送，不添加隐藏前后缀；换行、首尾空格、代码块和 Emoji 不被格式化器重写。
- 图片/文件以可删除 chip 显示。附件未完成上传和校验前禁用发送，并明确展示进度或失败。
- 软键盘弹出时输入器始终可见；时间线保持用户当前阅读位置，不强制跳到底部。

### 4.5 审批与提问

- 需要用户处理时，在时间线插入摘要卡并打开可关闭的底部详情面板。
- 详情至少展示主机、任务、动作类别、命令/目标、风险、产生时间和是否仍有效。
- “拒绝”与“一次批准”分离，批准不是默认高亮的误触目标；不提供自动批准。
- 请求归属、协议或实时状态不明确时只展示只读卡片，不显示可执行按钮。

## 5. 视觉与响应式

- 首要视口：360 × 800、393 × 873、412 × 915；覆盖 Android 构建、Android Chrome 和 Web 宽屏。
- 使用官方相近的中性灰阶、留白密度、圆角和排版层级，但所有值落到本项目自己的 Design Token。
- 首版同时支持浅色/深色；先保证系统主题跟随，不增加复杂主题编辑器。
- 可点击区域不小于 44 CSS px；兼容屏幕圆角、底部手势条、状态栏和 `safe-area-inset-*`。
- Android 返回键优先依次关闭附件面板、详情面板、任务抽屉，再返回上一页，不能直接退出应用或丢草稿。
- 宽屏只把抽屉固定为左栏，并可增加详情栏；对话组件和协议状态保持同一套实现。

## 6. P0 交互状态

| 状态 | 手机端表现 |
| --- | --- |
| `syncing` | 时间线骨架 + “正在同步”，写操作暂不可用 |
| `running` | 顶栏/底部显示运行中，发送键变为停止或协议允许的补充动作 |
| `waiting_approval` | 任务行和对话页均有明确待处理标记 |
| `waiting_input` | 在对应消息处提供回答输入，不混入普通审批 |
| `completed` | 普通可续聊状态 |
| `failed` | 就地错误与明确重试，不丢输入草稿 |
| `unknown` | 只读提示，隐藏高风险动作 |
| `offline` | 顶部离线条、最后快照时间和本地草稿；不静默排队批准 |

发送反馈必须区分“正在发送、Relay 已转发、本机已接受、失败”。网络恢复后依靠 snapshot + cursor 重建，不让旧乐观 UI 冒充真实 Codex 状态。

手机持有的设备授权若已在Host撤销，Relay可以保持不可枚举失败；UI在持续重连态仍必须显示用户可点击的“清除旧授权并重新配对”，清除范围仅限当前浏览器的Codex Plus IndexedDB。清除后回到8位配对码输入入口，不要求用户清站点全部数据或再次扫码。

## 7. 首版验收

- 360px 宽安卓真机可在两次主要点击内打开最近任务并开始输入。
- 可在两次主要点击内打开相机/相册/文件选择器，并能在发送前删除误选附件。
- 软键盘不遮挡输入器；旋转屏幕、切后台再回来不丢草稿。
- 抽屉、底部面板、代码块、长命令和 diff 不造成页面横向滚动。
- 等待批准、主机离线、Relay 在线但 Agent 不可用等状态可以一眼区分。
- 同一任务在 Android、电脑 Web、Codex App 和 VS Code Codex 之间续聊时，时间线不重复、不串线。

## 8. 实现顺序

1. 保持已冻结的 DSH-derived 组件树和正式/preview 构建隔离，不再更换前端基座。
2. 通过 `CodexServeClient` transport adapter 接入配对、snapshot/delta、审批和断线恢复。
3. 用官方 Codex schema 与 `ThreadItem` 校正真实 task/turn/item 投影，未知能力继续 fail-closed。
4. 文本链路、恢复和配对稳定后再接附件 transport，不让附件阻塞首个真实闭环。
5. 用 360/393/412px 视口与 Android 真机验证布局、键盘、安全区、返回键和后台恢复。

首版界面以开源上游的可追溯实现为基准。上游变化不自动形成阻塞；只吸收能提升核心手机操作的变化。
