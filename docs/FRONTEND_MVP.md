# 前端 MVP 实现边界

> 2026-08-23 路线更新：本文的状态、安全与移动交互要求继续有效；最终组件树改为 `docs/DSH_UI_ADOPTION.md` 定义的 DSH-derived React Web/PWA。下文提到的 Happy/Expo 文件只作为迁移期回归证据，不再是最终实现约束。

> 状态：2026-08-23 前端阶段已完成。本文冻结现有 UI、安全与移动交互边界；当前实现转入 `REMOTE_LINK_HANDOFF.md` 的 R1–R6。

## 1. 完成定义

前端完成不是重新画一个静态壳，而是把固定 DSH UI 源码的数据层替换为 Codex Plus `CodexServeClient`，形成一套桌面/手机共用且可独立验收的产品界面。旧 Happy Expo 客户端在切换完成前仅用于对照已验证行为：

- Android 浏览器与电脑 Web 共用同一 React DOM/Vite/PWA 组件树、主题、响应式布局和消息组件。
- 所有用户可达入口只服务 Codex；不出现 Claude、Gemini、OpenClaw、Rig、好友/Inbox、购买、语音或 Happy 托管产品面。
- 配对、任务列表、新建任务、对话、附件、审批/提问、连接状态和设置都有完整的 loading、empty、offline、error 与 disabled 表现。
- 在后端尚未接通时，使用编译期开启的本地 fixture 预览真实组件；预览不进入正式构建、不发送网络请求、不伪装成已连接。
- 正式与预览使用 Vite mode 编译隔离；构建后必须断言正式产物不含 fixture 标识并在浏览器显示未配对页。
- 后续 Windows Agent/Relay 只替换数据与动作适配器，不再重做页面结构。

## 2. 产品模式

### 2.1 正式模式

1. 未配对：手机直接打开正式站点首页，先登录 owner 账户，再输入已授权电脑 `/manage` 生成的 8 位配对码。页面不请求相机，也不暴露任意 Relay 地址或原始 invitation 输入。
2. 已配对但离线：展示最近快照、最后在线时间与本地草稿；所有高风险动作禁用。
3. 已连接：进入任务列表，选择/搜索/新建任务并打开对话。
4. 状态不确定：保持只读，不提供批准、发送或中断按钮。

正式模式不得提供“创建 Happy 账户”、Happy 托管回退或 OpenAI token 输入。
未配对时，除连接首页与 Relay 配置页外的所有深链必须重定向到连接首页；不能仅靠隐藏导航保护任务、设置或会话页面。

### 2.2 前端预览模式

当前交付链路只通过固定 Vite preview mode / `VITE_CODEX_PLUS_PREVIEW=1` 启用预览。旧 Expo 壳仅作历史回归参考，不属于正式交付链路。预览数据固定在源码 fixture 中，只包含虚构的主机、工作区和任务：

- 任务列表：运行中、待批准、已完成、离线。
- 对话：用户消息、Codex Markdown、代码、命令、文件修改/diff、计划、错误和附件。
- 控制状态：流式运行、一次性批准/拒绝、提问、发送阶段、断线只读。
- 预览动作只改变本地 fixture 状态或展示说明，不调用 Relay/app-server。
- 预览发送图片时，所选本地 URI 只用于生成 fixture 附件消息并在时间线展示；不发起上传或下载 RPC。
- 页面必须持续显示“离线 UI 预览”，不能只在深层面板提示；正式构建门禁必须断言 fixture 标识不存在。

## 3. 信息架构

```text
未配对
└─ 连接 Windows 主机
   ├─ 扫描二维码
   ├─ 粘贴一次性连接码
   └─ Relay 地址

已配对
├─ 任务
│  ├─ 搜索 / 新建
│  ├─ 最近任务与状态
│  └─ 对话时间线 + 输入器
└─ 设置
   ├─ Windows 主机与连接状态
   ├─ 已连接设备 / 撤销
   ├─ Relay 地址
   ├─ 外观与语言
   └─ 安全、版本与开源许可
```

移动 Web/Android 只保留“任务、设置”两个一级入口；删除 Inbox/好友。宽屏固定左侧任务栏，对话仍使用同一消息组件树。

## 4. 页面要求

### 4.1 连接页

- 使用 Codex Plus 自有文本标识和现成输入/按钮组件。
- 明确说明 OpenAI 登录只留在 Windows Codex，本页面不会索取账号或 token。
- 配对码只允许 8 位 Crockford 字符，大小写不敏感并忽略空格/连字符；兑换必须走 owner-authenticated same-origin POST。成功后页面把返回 fragment 交给既有本地 pairing 流程并立即清除 URL fragment，错误/过期/重复码稳定失败。
- 扫描成功立即停止全部 media track 并导航到配对路由；取消、权限拒绝、组件卸载和检测失败也必须停止相机。相机权限只允许 self，microphone/geolocation/payment/usb 继续禁止。
- 本机 Demo 开发模式使用固定测试账户 `admin` / `123456` 登录；提交后由 loopback Companion 返回一次性 invitation，并在页面内自动完成既有 E2EE 配对。该表单和接口只用于 `127.0.0.1` 开发服务，不进入正式部署入口，也不替代生产配对协议。
- 默认 Relay 为 loopback 开发地址；非 loopback 必须是 HTTPS。
- 连接码错误、过期、Relay 不可达和主机离线分别显示。

### 4.2 任务首页

- 顶栏显示 Codex Plus 与 Windows 主机连接状态。
- 手机端提供搜索、新建任务和最近任务；每行包含标题、工作区短名、更新时间与文字状态。
- 新建任务只允许 Codex，工作区只能来自 Agent 提供的授权列表；不显示 worktree 开关。
- 空任务、同步中和离线快照都有独立状态。
- 本机 Demo 全功能模式分页读取全部本地任务并统一归入“本机任务”；绝对 cwd 不进入 Web。点击“新建任务”打开最小输入面板，固定在 `codex-plus` 工作区创建，使用当前模型/effort/permission，不切换或修改任何已有进行中任务。

#### 4.2.1 Codex 风格宽屏侧栏

- 宽屏任务栏按工作目录/项目文件夹分组；项目标题使用文件夹图标和目录短名，任务作为其下一级纯文字行。主机名、技术 id 和任务计数不占据常态主视觉。
- 常态项目容器和任务行均为透明背景，不使用整组圆角卡片、分割线或阴影。只有当前路由对应的任务显示圆角选中底板；按下/悬停可以短暂出现同形反馈，但不能形成常驻卡片墙。
- 深色桌面基准以用户提供的 Codex App 截图取样：主工作区 `#181818`、侧栏 `#1E2024`、当前任务底板 `#303135`。文字与分隔色必须保持中性灰，避免 Material 紫灰偏色。
- 宽屏固定侧栏目标宽度约 `280px`，不再按 30% 扩张到 `360px`；1024px 及以上仍应给对话正文保留主要宽度。
- 宽屏对话正文与输入器最大宽度收敛到约 `736px`；桌面输入器圆角约 `16px`，避免现有 28px 药丸感。手机输入器继续使用独立的触控尺寸 Token。
- 手机任务首页继续采用适合触控的信息密度；本条仅改变宽屏固定侧栏的 presentation，不改变项目分组数据或任务协议语义。

### 4.3 对话

- 保留当前 DSH-derived conversation、message、composer、tool/diff/approval 组件；DSH runtime/session hook 已替换为 React props 与 `CodexServeClient` view model。
- 用户消息紧凑，Codex 正文全宽；命令、工具、diff 和审批为可折叠卡片。
- 官方 `webSearch` thread item 作为已完成的只读工具行展示查询摘要；它不应让整个已完成任务变成不可读取。其他未识别 item 仍按 compatibility omission 处理并关闭写能力。
- 输入器支持多行原文、图片/文件 chip、发送/停止；离线或 unknown 时只读并说明原因。
- `turn.send` 已返回 `accepted` 后必须在对话时间线末尾进入中性的“正在思考”运行态并自动轮询任务结果；`queued` 是结果不确定，不得冒充 accepted/running，必须保留草稿、显示“不要重复提交”并立即读取 fail-closed 快照。状态不能绝对定位到输入器上方造成重叠。运行态采用单请求串行的 500ms `task.read`，动作回执在途时暂停，且拒绝 host/generation 或 revision 倒退的快照；同 revision 的运行中快照若消息减少继续等待，但 authoritative terminal 快照必须结束本地 running，并暂时保留已 accepted 的乐观用户消息直到后续投影追平，不能要求刷新页面才能继续输入。运行期间输入器保持可输入，发送的新消息显示为贴在输入器后方的紧凑排队行；默认在当前 turn 完成并取得新 revision 后按先进先出提交。队列行的“调整方向”通过受控 `turn.steer` 立即插入当前 turn，删除只移除本地队列。只有动作被拒绝、连接失败、结果不确定或结果明确失败时才显示错误。
- 已保存设备授权持续认证失败时，重连页必须提供明确的“清除旧授权并重新配对”出口。该按钮只在用户点击后清除当前浏览器自己的 IndexedDB 设备/会话记录并返回首页配对码输入，不撤销或修改其他设备；不能让已被Host撤销的授权永久困在自动重连循环。
- D9.3取消新增设备二维码：电脑`/manage`显示8位配对码和复制按钮；未配对手机在owner登录后显示配对码输入框。兑换成功后页面内部进入既有`/pair#fragment`流程，已授权电脑发起的邀请由Windows后台自动批准。配对成功后不再显示配对入口，后续账密登录直接恢复设备会话。
- 附件 UI 只在真实 capability 存在时启用；生产附件 transport 在文本链路、恢复和配对稳定后实现，届时批次必须原子入队且失败时保留草稿与附件。
- 本机附件首个完整 slice 支持图片和普通文件：浏览器只读取用户明确选择的文件，显示可移除 chip，并把 bounded bytes 放进既有 E2EE turn 请求。排队项必须连同附件快照一起保存；发送成功前不得清空附件。图片允许在浏览器端缩放/压缩以满足协议上限，普通文件超限直接提示而不截断。
- 手机浏览器中的权限、模型与推理强度控件必须可实际操作，不能因为复用原生菜单壳而退化为无响应图标。
- 批准只能“一次批准”或拒绝；不出现自动批准和 session-wide 提权。

#### 4.3.1 Codex 风格输入器控制条

- 输入区与控制条共用一个大圆角容器，不再用齿轮把权限、模型和推理强度堆进同一张设置卡片。
- 控制条固定为：左侧 `+`、权限；弹性空白；右侧模型、推理强度、发送/停止。360px 下允许截断模型名称，但权限和发送按钮不能被挤掉；Codex-only MVP 不因参考图出现麦克风而恢复语音入口。
- `+` 打开一块靠近输入器的圆角菜单。首版只展示已接通的图片/附件动作；文件夹、目标、计划模式及插件必须等 Agent 明确声明真实能力后再出现，不能为了复刻参考图展示假功能。
- 权限菜单显示“请求批准”“只读”，并把参考界面中的“帮我批准”“完全访问”作为不可操作的说明项。MVP 中后两项始终禁用；手机不能为当前或后续任务提权。若未来增加 Windows 本机一次性能力，必须先单独更新安全设计与验收，不能由这份视觉规格隐含授权。
- 模型与推理强度分别从右侧文字按钮打开，不经二级“设置”页面。触发器默认透明、无边框；按下或菜单展开时才出现轻量圆角底色。
- 每个菜单本身只是一块圆角浮层；普通选项不再套独立卡片。权限菜单可以保留选中底板；模型与推理强度按最新 Codex 参考图只用末端勾选表示当前项，不再给当前行常驻填充。选择完成后的触发器/浮层关闭动画保持 160–200ms，并遵循系统“减少动态效果”。
- Web、Android 使用同一选项文案、层级和安全语义；平台只负责触控、键盘、安全区和返回键差异。

#### 4.3.2 模型与推理强度菜单细节

- 模型菜单为右对齐的单列浮层：桌面目标宽度约 `352px`、最大高度约 `360px`，16px 左右圆角；行高约 `36–38px`，14–15px 中等字重。常态没有图标、radio 圆点、分割线或独立卡片，当前模型只在右侧显示勾选。
- 推理强度菜单使用更窄的约 `228px` 浮层，顶部保留“推理强度”小标题；选项仍是透明单列行，当前项在右侧勾选。能力目录提供说明时，说明作为当前项下方的 12px 次级文字显示，不在客户端臆造模型能力。
- 浮层深色背景使用与 Codex 菜单一致的中性 `#2D2D2D`，hover/focus 仅出现轻微同形底色；浅色主题使用对应的高层 surface Token。模型列表与 effort key 必须来自 Agent/app-server 能力目录，截图中的具体版本名只用于 fixture 与视觉验收，不能成为执行层硬编码真相。
- 三处输入器（任务对话、任务首页、新建任务）必须共用同一菜单组件和 appearance；不得分别维护三套尺寸、图标或选中规则。

#### 4.3.3 桌面任务标题与右上环境工具

- Web 宽度 `>=900px` 时，任务头部与主内容面板同宽，不再跟随 736px 对话列居中。任务标题位于内容区左上，使用文件夹图标 + 单行任务标题；项目文件夹只作为路径/辅助信息，不再排在任务标题前面形成居中的面包屑。窄屏继续使用现有返回键与居中移动标题。
- 桌面正文采用比手机更紧凑的排版：Agent Markdown 正文目标 15px/23px，工具行保持 13–14px；手机仍保留 16px 可读字号。不能通过整体缩放页面来伪造紧凑效果。
- 右上工具区依次提供“打开位置”、环境信息、文件侧栏三个控件。现阶段没有 Windows Agent 的打开 IDE/资源管理器 RPC，因此“打开位置”下拉只允许真实的复制工作区路径；远程打开动作必须明确显示为未接通，不能点击后伪装成功。
- 环境信息控件打开约 300px 宽、24px 圆角的右对齐浮层。浮层只展示已有状态：变更数量、本机/工作区、Git 分支、拉取请求可用性、子任务统计和当前已加载来源；未知或协议未提供的值显示“不可用/暂无”，禁止从文件名、任务标题或旧缓存猜测。
- 文件侧栏控件只在当前任务明确支持文件浏览和 shell、宽度 `>=1100px` 时启用；打开“变更”必须复用现有受控文件侧栏。预览数据只能读取本地 fixture，不得因此触发真实 session RPC。
- 浮层深色背景使用 `#2D2D2D`，正文 13–14px、次级文字 12px；普通行透明，仅 hover/pressed 出现轻量同形底色。桌面头部高 48px，标题 14px/20px；“打开位置”使用 28px 高描边胶囊，环境按钮使用 28px 圆角底，文件侧栏按钮保持透明。禅模式折叠左栏时，左侧标题必须为全局导航按钮预留空间。
- 手机与窄屏 Web 不显示桌面三按钮组，而在顶栏右侧提供一个 44px“环境信息”入口。入口打开底部 sheet，忠实保留环境、变更、本机/工作区、Git、子智能体和来源信息；sheet 顶部圆角 24px、最大高度不超过 `calc(100dvh - 72px)`，内部滚动并适配 safe area。变更只有在真实能力成立且非 preview 时进入全屏 diff；来源“查看全部”只处理已加载本地数据；Windows 打开、提交/推送等未接通能力继续禁用。遮罩、关闭按钮和系统返回键均先关闭 sheet。

#### 4.3.4 对话回合索引（Conversation minimap / message anchor rail）

- Web 桌面宽度 `>=900px` 且实际任务详情区宽度 `>=800px` 时，在详情区最左缘显示一列用户消息锚点；每条已加载且可见的 `user-text` 对应一个 tick。该控件称为 conversation minimap/message anchor rail，本质是带 hover preview 的 anchor jump navigation，不是进程协议或模型能力。右侧文件栏挤窄详情区后必须自动隐藏，不能覆盖正文。
- 基线采用 Apache-2.0、高 Star `iOfficeAI/AionUi` 的 `MessageAnchorRail` 固定间距、宽命中区、磁吸最近锚点和邻近 tick 渐变算法；当前实现为 React DOM 组件并保留来源归属。不得引入其 Electron、数据库或全历史读取链路。
- 常态 tick 约 `6×2px`；hover 最近项扩展至约 26px，两侧邻项依距离依次缩为 20px/14px/10px。tick 使用固定 10px 节距，不因长回复压缩；超出可视容量时仅索引列内部滚动。宽 36px 的透明命中区负责选择最近 tick，用户不必精确点中 2px 线。
- hover/focus 卡片显示该条用户消息的本地摘要，最多三行并截断；不得请求 Relay、读取未加载历史、解析工具结果或把摘要写入日志。点击、Enter 或 Space 使用当前 DOM 列表滚动能力将对应消息放进不受头部/输入器遮挡的视口中部，不能因动态消息高度失效。
- 索引按对话时间从旧到新排列，但必须保存其在 newest-first `displayItems` 中的真实索引。任务切换、分页、流式更新和分组折叠后需重新映射；只有一条用户消息时隐藏。控件只在桌面显示，窄屏/手机不占正文触控区域。
- `role=navigation`，每个 tick 提供回合序号和消息摘要的可访问名称；当前 hover/focus 项用 `aria-current`。预览模式只执行本地滚动，不触发任何 session/文件/同步 RPC。

### 4.4 设置

- 保留连接、设备、Relay、外观、语言、安全与许可。
- 删除账户社交资料、Claude/GitHub 服务连接、订阅/购买、语音、好友、反馈拉新和 Happy CLI 安装说明。

## 5. 组件采用规则

- 优先修改可见入口与配置，保留上游成熟 renderer；不为了“代码干净”一次删除所有暂时不可达内部模块。
- 前端数据与动作统一经 `CodexServeClient` 适配边界进入：任务 snapshot/delta、连接状态、附件状态和动作结果。fixture 与 Relay-backed adapter 必须实现同一契约。
- 预览 fixture 不读取 Codex home、工作区文件或真实任务，不落盘对话正文。
- 用户输入动作保持原字符串；UI 不能 trim、包装或批量合并后再交给适配器。

## 6. 验收矩阵

| 范围 | 验收 |
| --- | --- |
| 视口 | 360×800、393×873、412×915、≥1024px |
| 主题 | 系统浅色、深色 |
| 页面 | 连接、任务列表、新建任务、对话、审批、附件、输入器四类菜单、设置 |
| 状态 | loading、empty、running、waiting approval/input、completed、failed、unknown、offline |
| 可用性 | 44px 点击区、无横向页面滚动、输入器不被软键盘遮挡、Android 返回键先关面板 |
| 品牌 | 可达 UI 无 Happy/Claude/Gemini/OpenClaw/Rig/购买/好友/语音入口 |
| 浏览器 | 0 runtime error；预期离线不产生未处理异常 |
| 工程 | `pnpm typecheck`、`pnpm test`、Web 正式/预览导出均通过；正式静态产物断言 preview flag 关闭 |

## 7. 本轮实施顺序

1. R1：共享协议与 transport adapter 骨架。
2. R2：loopback Relay 与测试双端。
3. R3：二维码配对、设备撤销与 E2EE。
4. R4：Windows Companion 与官方 app-server。
5. R5：正式 Web 经 `CodexServeClient` 接线；R6 再进入 Debian/阿里部署。
