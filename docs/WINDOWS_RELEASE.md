# Windows 本地服务启动器

## 隔离前端预览 / 2026-09-10

最新评审否定工业轨道背景。本轮撤下轨道、刻度、端帽、扫描点和切角装饰，改成画面边缘进入的宽阔雾面空间层、柔光和细微视差；形体无描边，正文后保持安静，连接仅带来一次柔和的环境亮度变化。保留用户此前认可的前景玻璃、开放布局、功能和统一 60 FPS，仍只做隔离预览。

前一轮曾尝试断续工业轨道，但该实现随后被用户否定，已撤下；背景视觉以本文件顶部新方案为准。前景与默认 60 FPS 的要求继续保持。

启用动画时统一以 60 FPS 为默认目标：WPF 时间线、循环呼吸、颜色、鼠标更新均采用统一节奏；背景和脏材质改由 CompositionTarget.Rendering 驱动，按累积截止时间限频并过滤同一呈现时间的重复回调，移除 33/50 ms 计时器造成的混合节奏。减少动态和隐藏清理保留。验证 60/120/144 Hz 输入下的调度及本机渲染回调，不将回调数量或 CPU 耗时宣称为实际显示器稳定帧率。

背景始终位于全部内容之后，不命中鼠标，右侧正文区域以透明度遮罩降低强度，保留淡色/深底、开放布局与原功能。当前为无描边的雾面空间层；采用小型 WPF 几何，不安装 React/WebGL 框架。最小化/隐藏/减少动态立即停止并清除瞬态，关闭清理。

本轮继续依据 RhineLabUI 源码细化材质与动作配合：保持已认可的开放构图和淡色主题，将薄片底色与文字先正确合成后统一受光，减少多层发光相加造成的泛白；扣合之后由斜向光线带动逐行清晰变化，扫描线与粗糙度读取同一显示位置；配对区展开时薄片同步轻抬/靠近，关闭时归位。缩短为适合服务启动器的过渡，不照搬上游长解密过程，不改变按钮可用时机。减少动态、断线与隐藏时立即取消扫描并落到当前状态，保留原线条揭示和本地隔离。

细节追加：用户认可开放式布局，本轮保持构图。配对区上下两条线分离为独立装饰，从中心向两端展开，关闭时从当前长度收回，减少动态直接落到终点。暖/冷配色整体降低饱和度，保留深色底与正文对比。左侧增加局部磨砂/折射材质：缓存薄片距离/法线场，用斯涅尔折射方向、Schlick 菲涅耳反射、预滤波背板与稳定微颗粒形成玻璃质感；文字和锁链独立叠加，保持清晰。悬停降低散射、移开恢复；只取样预览内原创合成背板，不抓取桌面或其他窗口。材质有变化才限频重算，隐藏/关闭停止更新，检查实际计算耗时。该效果是 WPF 中的局部光学近似，不声称调用原生 iOS Liquid Glass。

最新结构要求：用户否定承载所有内容的厚重圆角卡片，允许重新定义卡片概念。本轮参考 RhineLabUI 的实体薄片、空间分离和细线排版，将窗口改为开放式构图：左侧两层原创半透明连接薄片作为空间对象，右侧无外框的大字号状态、必要状态行与操作，配对区从下方抽出。移除原多重圆角外壳和整块表单底，保留暖/冷渐变与用户认可的锁链动效。薄片采用 WPF 自带的 Viewport3D 和简单原生几何，文字/按钮保持二维可读且直接可操作；不导入上游模型、WebView 或新渲染依赖。

本轮追加动效要求：未连接的两段锁链持续低幅轻颤，间歇向彼此试探；连接时先蓄力再快速扣合，随后有一次短促回弹、卡片冲击与光晕扩散。界面整体由烟熏琥珀/暖金渐变快速切到石墨/钴蓝/冰蓝渐变，覆盖底色、卡片、边缘和操作按钮，不用大面积纯黄或纯蓝。持续动作仅在可见的等待/连接/恢复状态运行，成功后停止抖动；减少动态立即停止循环和冲击，只切换最终配色。快速断线或反向操作取消旧的成功效果，继续保持独立模拟与真实服务隔离。

用户已批准从预想图进入隔离前端实现。预览位于 apps/windows-companion-preview，使用独立进程名和入口，不编译/调用正式后台控制类，也不读取本地服务配置、密钥或登录任务。所有按钮驱动固定的模拟状态；窗口标明预览，不产生真实配对码。预览输出与检查截图位于 .tmp/windows-ui-preview，正式 release 和运行服务不变。

动效包括锁链分离/扣合及黄色/蓝色切换、状态文字揭示、薄片三维转向/分合、按钮压下回弹、配对区收展和占位字符渐显。使用原生 WPF Viewport3D 表现两片原创连接薄片，移除了旧版堆叠圆角容器与二维倾斜模拟；不加入 Three.js/WebView 或机械核心。支持减少动态、最小化暂停、快速反向与新状态取消旧计时动作。预览通过后再按后续指令接入真实状态，本轮不迁移正式代码。

预览已实现：双击 `.tmp/windows-ui-preview/CodexPlusUiPreview.exe`，点击“播放演示”可观察含最后材质过渡约 10 秒的模拟过程；鼠标在左侧薄片上移动可改变三维视角。“减少动态”会立即关闭装饰过渡。窗口默认 740×500 DIP，最小宽度 700 DIP；配对信息在底部独立展开。构建入口为 `powershell -NoProfile -File scripts/windows-ui-preview.ps1`，加 `-BuildOnly` 只构建并检查；代码与操作说明见 `apps/windows-companion-preview/README.md`。

独立原生检查通过 111 项断言，覆盖交互/材质/布局/生命周期与新背景，保留统一 60 FPS、30/60/120/144 Hz 输入的截止时间、重复合成时间去重、长帧后无补发突发及原生时间线设置。检查截图保存在 `.tmp/windows-ui-preview/checks`。此次完成合成状态和原生渲染验收，未验证真实连接、配对或生产服务，不将预览程序作为正式 release。

玻璃使用缓存的 192×256 几何场和可分离高斯预滤波，脏状态由 60 FPS 合成时钟处理，锁链自身动画不触发材质重算。2026-09-10 本机各 30 次材质计算与同步 WritePixels 调用：完整清晰状态 p50=2.76 ms、p95=2.97 ms，扫描状态 p50=2.99 ms、p95=3.45 ms。玻璃静止/隐藏时更新计数保持不变，关闭后取消订阅。

当前背景只有三层静态平面、共 12 顶点，更新仅改变光照透明度和位置。30 次更新 p50=0.005 ms、p95=0.019 ms；原生离屏检查期间 1.20 秒内观察到约 59.9 次/秒 WPF 背景渲染回调。60 FPS 是默认目标；CPU 测量不包含 GPU 绘制/屏幕呈现，WPF 回调率也不是显示器稳定帧率认证。正文区域的透明度遮罩和鼠标命中隔离保持。

## 动效预想 / 2026-09-09

本阶段先出关键帧概念图，不改实现。保留石墨深色、系统蓝、圆润卡片与最小服务窗口，只借鉴可中断的淡入/抬升、状态揭示和展开过渡；配对信息仍只由真实本机操作与后台结果驱动。任何光效都不能充当登录/服务成功凭据，功能可用时不等待装饰动画。

用户认为首版过于克制，随后允许小型、纯装饰的 3D 效果。新概念在服务卡片里加入悬浮几何核心，用散开/合拢和微小鼠标视差呈现玻璃与金属的立体感；业务操作保持原有范围。本阶段仍先审阅预想图，不直接实现或加载新的渲染依赖。

后续评审已否定机械核心风格。方案以锁链标志为动效重点：等待为断开的黄色两环，真实连接成功后对齐扣合转蓝，断线按实际状态退回；服务卡片采用薄层玻璃/轻微视差，按钮轻压回弹、状态文字擦入、配对区域分层展开。当时仅改变标志配色；用户在隔离预览评审后明确扩展为整窗暖/冷渐变切换，以本文件顶部追加要求为准。保留停止动态效果和不阻塞实际操作的要求。

## 2026-09-09 稳定性验收要求

- 用户确认黑框表现为窗口仍在、内容黑掉或空白。检查托盘隐藏、重复双击软件、最小化恢复与启动中请求显示；必须使 WPF 的可见状态与原生窗口同步，不能只调用原生 ShowWindow 绕过 WPF 生命周期。
- Windows 事件记录还确认两次本项目崩溃：OwnedProcess 的 Exited 回调在 Process 已释放后读取 ExitCode，抛出 InvalidOperationException。退出通知、读取退出码与 Dispose 必须互斥，正常停止/关闭不得留下未处理异常或 owned 子进程。
- 按现有简洁窗口修复，不增加管理台、全局图形设置或后台自动执行任务。回归要覆盖真实隐藏/重新显示与子进程停止/Dispose 竞争，保留原有启动、安全关闭及设备绑定能力。

## 职责

产品只有三个部署角色：Windows 笔记本运行本机 Codex 服务；阿里服务器通过宝塔/Docker 运行 Gateway；安卓手机通过浏览器使用业务功能。

Windows 软件仅负责让本机官方 Codex app-server 与 Companion 出站连接可用，并提供一次性的“连接手机”入口。任务、对话、模型、审批及设备管理都在网页；不再做 Windows 管理台。v0.1–v0.3 的界面历史见 PROGRESS.md。

## 使用

1. 完整解压 release，双击 `CodexPlusCompanion.exe`。
2. 点击“启动服务”，等待本机 Codex 和远程通道就绪。
3. 在安卓浏览器打开 `https://gateway.example.com`，自行登录；若要求配对码，在 Windows 软件点击“连接手机”，输入窗口显示的 8 位码。每个浏览器使用独立的一次性码，配对后自动保存授权。
4. 关闭窗口会保留托盘；停止按钮或托盘“退出并停止”才关闭本项目后台。

窗口只保留启停、“连接手机”、两项必要状态和简短错误原因，没有导航、设置、日志面板、图表或网页入口。普通打开不自动启动服务；既有用户已配置的登录自启仍由当前用户任务保留，兼容入口 `--background` 不增加新的自启操作步骤。

“服务可用”须同时具备官方 app-server 的可写兼容绑定和 Host 连接；只读、引擎未就绪、断线或异常均如实显示。GUI 不凭旧日志或只看到 Gateway connected 就宣称可用。

## 实现边界

- 保留同一普通 Windows 用户环境，不覆盖 CODEX_HOME、不读取/复制凭据，不控制 Codex App/VS Code。
- 继续复用工作区 `.data/windows-companion` 的设备授权及持久动作状态；一键启动按精确项目路径处理旧 Companion，Job 只管理软件自己创建的进程树。
- 主动 stop 走私有 stdin 与原有正常关闭流程；超时/崩溃仅清理 owned Job。原有加密和失败关闭原则不变。
- release 带 Node、Companion bundle、官方 Codex CLI 0.153.4 及资源、DPAPI helper 和许可证；不包含身份、凭据、对话、缓存或日志。

## 无已配对浏览器时的连接恢复 / v0.5.0 起

用户已登录 Owner，但电脑和原手机都停在配对码输入页。当前 Web 仅在安全设备存储没有授权记录时返回无错误的未配对页；账号登录不会创建或找回设备私钥。现有 `/manage` 生成配对码依赖先有已授权浏览器，因此不能覆盖首次使用或全部浏览器授权不可用的恢复场景。

用户已明确同意这一最小操作：Windows 服务就绪后提供一个“连接手机”按钮，本机用户点击才创建五分钟、一次性的 8 位配对码；手机仍须登录 Owner 后输入，后续沿用现有不可导出设备密钥与 E2EE 流程。Windows 不增加任务、设备列表或设置面板。配对码只在本机窗口短暂显示，经父子进程继承的私有 stdin/stdout IPC 传递，由专用消息解析消费，不进入诊断事件、日志、文件、剪贴板或命令行；Gateway 仅接受当前已认证 Host 的登记，沿用既有内存容量、到期与一次性兑换规则。

2026-09-07 用户确认覆盖之前仅 E2EE 管理动作创建邀请的限制，新增可信本机点击这一来源；不清空或重建现有 Host 与设备授权。一个活动邀请期间禁用重复生成，配对完成、到期、停止或断线时清除窗口中的码；登记失败关闭本次邀请并允许重试。未收到本机点击仍拒绝未知/bootstrap invitation 的自动批准。
