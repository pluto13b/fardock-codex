# 账户登录与设备接入调研

日期：2026-09-09。范围是本项目自托管 Owner 账户，GitHub 发布账号不参与产品登录。本轮保留账户登录、Windows Host 授权与 E2EE，不直接替换认证方式。

## 当前问题和职责

| 层次 | 当前实现 | 用户应看到的行为 |
| --- | --- | --- |
| 账户登录 | Gateway 验证 Owner 口令，签发内存会话 cookie | 确认是谁在使用服务；过期后重新登录账户 |
| 首次设备绑定 | Windows 或已授权网页创建一次性码，Host 签发设备授权 | 只在新增浏览器或授权确实不可用时出现 |
| 日常连接 | 浏览器用保存的不可导出密钥恢复 E2EE | 自动恢复；切后台、网络中断不能引导用户删除设备密钥 |

源码中，Owner 会话与浏览器 IndexedDB 设备授权彼此独立。Gateway 更新会使内存登录会话失效，但不会删除浏览器密钥。此前“已登录却要配对”的截图还可能处于授权加载前的界面；手机随后已用原授权恢复。本轮另复现了 Windows 原生显示与 WPF 隐藏状态不一致，造成生成码的软件窗口不可用。这些入口缺陷应与认证机制分别处理。

当前账户会话最长 12 小时、最多 8 个，仅存于 Gateway 内存。服务器容量也必须先具备可写条件：此前已出现设备授权落盘 ENOSPC，本轮又发现磁盘满。修改登录方式不能掩盖授权无法持久化的基础故障。

## 标准与工程依据

- RFC 8628 面向缺乏方便输入/浏览器的设备，使用另一台设备审阅授权，并明确讨论用户码暴力猜测、远程钓鱼和识别设备。它可借鉴交互，但本项目的短码兑换与 signed invitation 并不是完整 OAuth Device Grant 实现，也不能照搬成“登录后自动批准任意设备”。[RFC 8628](https://www.rfc-editor.org/rfc/rfc8628.html)
- 会话过期、轮换和退出属于账户会话管理。延长登录体验仍需保留服务端失效能力，不能通过永久 bearer 或关闭过期检查处理；重新登录不应连带删除独立设备密钥。这是结合本项目分层后的设计结论。[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- 重新认证适合账户恢复、口令重置等风险事件。把普通断网当作重新绑定设备的理由，会造成不必要的操作和授权丢失。[OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)
- WebAuthn 区分可备份的多设备凭据与单设备凭据，并要求考虑设备丢失后的恢复。Passkey 可以增强账户认证，但本项目现有 ECDH/ECDSA 设备密钥并非 WebAuthn 凭据；添加 Passkey 不会自动找回这些密钥。[W3C WebAuthn](https://www.w3.org/TR/webauthn-3/)

## 方案比较

| 方案 | 首次使用 | 日常使用 | 本项目结论 |
| --- | --- | --- | --- |
| 账户 + 现有一次性码 | Windows 生成，手机输入一次 | 账户登录后恢复设备 | 当前实现保留；修好窗口、恢复提示和状态分类 |
| 账户 + 手机申请 + Windows 一次允许 | 手机点申请，电脑软件点允许 | 账户登录后直接恢复 | 建议作为下一阶段交互候选，需明确批准具体浏览器请求 |
| 账户 + Passkey | 注册验证器，可保留密码入口 | 可用生物识别/PIN 登录 | 后续可选增强；不能代替 E2EE 设备注册/恢复 |
| 仅账户口令即可新增远控设备 | 最少步骤 | 登录后自动进入 | 会扩大密码泄露后的影响，不在本轮直接采用 |

## 建议的下一阶段交互

账户登录继续保留。已绑定浏览器直接恢复；新浏览器主动点击“请求连接这台电脑”，Windows 软件短暂显示一张接入请求卡片，由本机用户允许一次。成功后保存浏览器自己的设备密钥，后续不重复接入。Windows 不增加任务列表或管理台，不要求扫码、SAS 或终端操作。

这是一项待确认的授权交互变更：批准必须绑定到一次性请求、该浏览器公钥和当前 Host，不能批准一个无具体对象的“允许所有登录设备”。到期、拒绝、Host 离线或请求替换均应终止；浏览器名称/UA 只作提示，不能充当身份凭证。去掉手抄码会失去当前带外秘密的一部分保护，也需要防范误批准。不能把这套专用设备接入流程宣传为直接实现了 OAuth 或 WebAuthn。

当前先完成项目目录与 Windows 生命周期修复。认证下一步应优先区分“账户过期”“未绑定”“设备已撤销/不可用”“连接恢复中”，避免普通重连页提供显眼的删除授权操作。是否采用上述免手抄码交互、是否延长账户会话，待用户讨论确认；不增加第三方身份服务或额外容器。

## 后续实施验收

- 新浏览器只有 Owner 登录和确切的 Host 批准均有效后才获得设备授权；密码、设备私钥和对话密钥不进入 Gateway 日志或持久状态。
- 错请求、公钥替换、并行请求、到期、拒绝和重放失败关闭；重试不创建重复授权。
- 已绑定浏览器在账户重登、网络切换、Windows 重启后恢复原授权；真实丢失/撤销时才引导重新接入。
- 现场以安卓浏览器完整操作验收，不能只以账户登录成功或窗口显示“服务就绪”宣称全流程完成。
